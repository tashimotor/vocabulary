# Печать словарных слов на карточках А6

## Суть

Список слов печатается как карточки формата А6 (105×148 мм, точный ISO-размер — не "100×150", те не делятся на А4 без остатка). 4 карточки кладутся на один лист А4 сеткой 2×2: 2×105=210 мм и 2×148=296 мм — ровно в размер А4 (210×297 мм), без полей и обрезков.

Если слов больше, чем помещается на одну карточку, список — как книжка: слова идут по алфавиту сквозным потоком через несколько уникальных карточек-страниц, а не мнутся на одну.

## Ёмкость одной карточки

На карточке — заголовок (например "2 класс") и список в 2 колонках. Ёмкость колонки (сколько слов помещается) и размер шрифта зависят от самого длинного слова/фразы в списке — их нельзя знать заранее, только подбором (см. ниже). В сессии-прототипе для списков из коротких русских слов получилось 14 строк × 2 колонки = 28 слов на карточку при шрифте 23pt (Times New Roman) — это стартовая точка для подбора, не константа.

## Алгоритм пагинации ("книжка")

1. Отсортировать весь список по алфавиту (даже если в исходном файле другой порядок — алфавитный порядок обязателен).
2. Разбить отсортированный список на страницы по N слов (N — ёмкость карточки, см. выше; обычно 28).
3. Пусть ROWS — ёмкость одной колонки на полной странице (обычно 14, т.е. N/2, см. выше). На любой странице (и полной, и последней неполной) колонка 1 = первые `min(n, ROWS)` слов, колонка 2 = оставшиеся `n - min(n, ROWS)` слов — так и полный список слов страницы читается по алфавиту (сверху вниз в колонке 1, потом сверху вниз в колонке 2). На полной странице это то же самое, что `ceil(n/2)`/`floor(n/2)` (28 слов → 14/14).
4. `grid-template-rows` в `.words` на ЛЮБОЙ странице — всегда `repeat(ROWS, 1fr)`, фиксированное число строк, одно и то же для всех страниц книжки. Так шрифт, межстрочные отступы и расположение слов на последней (неполной) странице визуально совпадают с предыдущими страницами — они не растягиваются на всю высоту карточки. На неполной странице колонка 1 заполняется целиком (если слов ≥ ROWS), а весь недостаток уходит в колонку 2 — там появляются пустые строки внизу (просто меньше `<div class="word">` в DOM, чем ячеек сетки — CSS grid сам оставляет лишние ячейки пустыми). Если слов в странице меньше ROWS, колонка 1 тоже получится неполной и пустой останется только её хвост — колонка 2 в этом случае пустая целиком.
5. Разложить страницы по листам А4 — по 4 на лист, по порядку.
6. Если слов на всё влезает ровно в 1 страницу (≤ N слов) — размножить эту единственную страницу на все 4 слота листа (даёт 4 готовых копии для вырезания — так и сделали для 1 класса).
7. Если страниц больше одной и последний лист А4 заполнен не полностью — оставшиеся слоты оставить пустыми карточками (только рамка для реза, без текста), а не дублировать чьи-то страницы — это книжка, а не тираж одной копии.

## Выделение орфограммы (не "любая безударная гласная")

Жирным — конкретная орфограмма слова (то, что не проверяется и нужно запомнить), а не механически любая безударная гласная:
- Обычно это непроверяемая безударная гласная в корне (определяется через постановку ударения — проверяемая гласная в ударной позиции не выделяется).
- Иногда орфограмма — согласная, не гласная: например "класс", "русский" — там жирным двойная согласная "сс", а гласных орфограмм в этих словах нет вовсе.
- Для словосочетаний (например "русский язык") — разбирать каждое слово по отдельности.
- Определять по факту для каждого слова; не подставлять шаблон.

## Единый размер шрифта — подбор рендером, не на глаз

Если заголовок и слова должны быть одним размером ("в едином"), заголовок делать коротким (например просто "2 класс") — иначе длинный заголовок физически не влезет в ширину карточки на большом кегле.

Подбор размера — только через рендер и замер, не через прикидку "на глаз":
1. Взять самую длинную строку списка (обычно самое длинное словосочетание, не одно слово).
2. Рендерить карточку в headless Chrome на кандидатском размере шрифта, увеличивая с шагом 1–2pt.
3. Проверять ДВА независимых ограничения:
   - **по ширине** — самая длинная строка не переходит на 2 строки и не упирается в границу колонки/карточки;
   - **по высоте** — все N строк (включая заголовок) помещаются в фиксированную высоту карточки без переполнения снизу.
   Ограничения independent — то, что влезло по ширине, может вылезти по высоте, и наоборот. Оба проверяются рендером страницы для печати (см. ниже), не скриншотом экрана.
4. Взять последний размер, прошедший оба теста; на 1–2pt больше — уже брак (см. частые ошибки).

## Генератор вёрстки (assets/generate_cards.py)

Пагинация, сетка и тайлинг на лист А4 — не набирать HTML руками, а собрать через `assets/generate_cards.py` (лежит рядом с этим файлом). Скрипт умеет только вёрстку (разбиение на страницы по ROWS-строкам согласно алгоритму выше, сетку 2×105мм/148мм, тайлинг 4 карточек на лист, дублирование на 4 слота при единственной странице). Сортировку по алфавиту и расстановку `<b>` для орфограммы он не делает — это лингвистическая работа, её нужно сделать заранее для каждого слова (см. разделы выше), результат передаётся на вход уже готовым.

Вход — JSON-файл:
```json
{
  "title": "2 класс",
  "words": ["<b>а</b>лф<b>а</b>вит", "б<b>е</b>рёза", "быстро", "..."]
}
```
`words` — уже отсортированный по алфавиту список, каждое слово/словосочетание — HTML-строка с `<b>` вокруг орфограммы (или без `<b>`, если её нет, см. "Определять по факту").

Запуск:
```bash
python3 .claude/skills/printing-vocabulary-cards/assets/generate_cards.py words.json \
  --font 20 --cap 28 --out N-class-print.html
```
`--font` и `--cap` (слов на карточку, чётное — строк в колонке будет `cap/2`) подбираются рендером под конкретный список (см. "Единый размер шрифта"), дефолты в скрипте — только стартовая точка. JSON-файл со словами — временный (например, в scratchpad); в репозитории хранится только вход (`N-class.md`) и результат (`N-class-print.html`), не забирать под версионирование сам JSON.

## Реализация (CSS-каркас, что генерирует скрипт)

```css
@page { size: A4; margin: 0; }
.sheet {
  width: 210mm; height: 297mm;
  display: grid;
  grid-template-columns: 105mm 105mm;
  grid-template-rows: 148mm 148mm;
  page-break-after: always;
}
.sheet:last-child { page-break-after: auto; }

.card {
  width: 105mm; height: 148mm;
  box-sizing: border-box;
  border: 0.35mm dashed #000;   /* линия реза */
  padding: 9mm 7mm;
  display: flex; flex-direction: column;
}
.card h1 { font-size: <N>pt; font-weight: bold; text-align: center; margin-bottom: 3mm; }

.words {
  flex: 1;
  display: grid;
  grid-auto-flow: column;
  grid-template-rows: repeat(<ROWS>, 1fr);  /* фиксировано, одно и то же число на всех страницах книжки */
  grid-template-columns: 1fr 1fr;
  column-gap: 6mm;
}
.word { font-size: <N>pt; line-height: 1; align-self: center; white-space: nowrap; }
```

DOM-порядок внутри `.words` — сначала ВСЕ слова колонки 1 (по алфавиту), потом ВСЕ слова колонки 2. Не чередовать (кол1-слово, кол2-слово, кол1-слово...) — `grid-auto-flow: column` раскладывает по позиции в DOM, а не по смыслу пар, чередование сломает алфавитный порядок внутри колонок.

## Частые ошибки

| Симптом | Причина | Починка |
|---|---|---|
| Пропадает пробел внутри фразы ("русскийязык" вместо "русский язык") | `.word { display:flex; align-items:center }` — у flex-контейнера с смешанными text+`<b>` детьми обрезается краевой пробел анонимного flex-item'а | Не центрировать через flex; `align-self:center` на обычном блочном элементе + `line-height` |
| Последняя строка карточки печатается ниже нижней рамки, при этом рамка не "разъезжается" | У `1fr`-строк грида есть неявный `min-height:auto` (по контенту) — если шрифт для одной строки не влезает в свою долю `1fr`, ряды строки молча раздвигают сетку за пределы фиксированной высоты родителя, без обрезки и без предупреждения | Всегда проверять реальным рендером в PDF на предельных размерах шрифта, не доверять "1fr" на слово |
| В превью на экране всё ок, а в реальной печати не влезает / другие поля | Скриншот показывает `@media screen`-версию (там может быть свой фон/отступы для удобства просмотра), не финальную печать | Проверять именно печатный вывод (см. ниже), не screen-скриншот |
| Список "не совсем по алфавиту" после ручной вёрстки | DOM-порядок в `.words` перепутан (см. выше) | Сначала все слова колонки 1 подряд, потом колонки 2 |

## Проверка перед сдачей

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --disable-gpu --no-sandbox \
  --print-to-pdf=out.pdf --no-pdf-header-footer file:///path/to/file.html
sips -s format png out.pdf --out out.png   # macOS, без ghostscript
```
Прочитать `out.png` (Read) и визуально сверить: рамки карточек ровно 105×148 мм и не выезжают за лист, самая длинная строка не касается границы, нижняя строка не упирается в нижний край, орфограммы выделены по существу (не шаблонно). `sips` растеризует PDF в низком разрешении (нечёткий шрифт мешает читать детали) — если нужна более чёткая картинка для проверки, дополнительно снять `--screenshot` в headless Chrome с `--force-device-scale-factor=3` (геометрия та же, если в файле нет отдельных print-only правил, отличных от того, что видно на экране).

Пользователю — печатать через браузер (Cmd+P): бумага А4, поля «Нет», масштаб 100%, фоновая графика не нужна (фон и так белый).
