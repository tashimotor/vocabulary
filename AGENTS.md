# Инструкции для AI-ассистента

Проект: подготовка списков словарных слов к печати как обрезные карточки А6.

## Правило

Для любой задачи «подготовь(-и) список слов к печати», «сделай карточки», «пересобери N-class» — сначала использовать скилл `printing-vocabulary-cards` (лежит в `.claude/skills/printing-vocabulary-cards/`, доступен только в этом проекте). В нём — точный формат карточки, алгоритм разбиения длинного списка на несколько карточек-страниц, правило выделения орфограммы жирным и порядок подбора размера шрифта. Не переизобретать вёрстку заново.

## Входные и выходные файлы

- Вход: `N-class.md` — список слов, по одному на строку, формат `<номер><таб><слово или словосочетание>`. Порядок в файле не важен, финальная вёрстка всегда по алфавиту.
- Выход: `N-class-print.html` — тот же класс, суффикс `-print`. Один самостоятельный HTML-файл (открывается в браузере, печатается напрямую), без внешних зависимостей.
- Перед тем как менять существующий `N-class-print.html`, свериться с актуальным `N-class.md` — список слов мог обновиться.

## Генератор вёрстки

Саму HTML-вёрстку не набирать руками — собирать через `.claude/skills/printing-vocabulary-cards/assets/generate_cards.py` (вход — JSON с уже расставленными орфограммами, подробности и формат в SKILL.md). Скрипт отвечает за пагинацию, сетку и тайлинг на А4; орфограммы и алфавитный порядок — задача ассистента, не скрипта.

## Обязательно перед сдачей результата

- Проверить итоговый файл рендером в headless Chrome (`--print-to-pdf` + растеризация) — не полагаться на то, что CSS-сетка «должна» влезть; шаг проверки описан в скилле.
- Каждое слово — орфограмма выделяется по факту (что в нём реально непроверяемо), не механическим правилом «выделить гласную».
- Если что-то в списке слов неоднозначно (например неясно, где ставить ударение, или встречается редкое/незнакомое слово) — спросить у пользователя, а не гадать.
- Если пользователь даёт эталонный файл с готовой разметкой орфограмм (сейчас поддержан xlsx, см. SKILL.md → «Сверка орфограмм с эталонным файлом») — сверить с ним свой разбор через `assets/xlsx_to_json.py` + `assets/compare_orthograms.py` и показать пользователю расхождения, а не подставлять эталон молча и не игнорировать разницу. Решение по каждому расхождению (принять эталон, оставить свой вариант) — за пользователем; собственные предположения о том, что в эталоне «опечатка», без подтверждения пользователя не вносить.
